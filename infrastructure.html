Design 1 — Secure Lab / Small Office Topology (Monitoring + Resilience)

This design is built for a home lab or small office where the goals are strong network security, repeatable operations, and centralized visibility (SIEM + SOAR), while still keeping the setup practical to run.

ISP Modem → Firewall → Router → Primary Switch (+ Backup Switch) → KVM → Endpoints ├─ Windows / macOS Workstations ├─ Linux / Kali (testing) ├─ SIEM (log collection + correlation) └─ SOAR (workflow automation) Power: Back-UPS for network + monitoring stack

What each component is doing

  • Modem: Terminates the ISP connection and hands off internet connectivity.
  • Firewall: The security perimeter (NAT, stateful filtering, threat controls, VPN, logging). This is where you enforce inbound/outbound policy.
  • Router: Handles internal routing (or you can collapse router/firewall into a single device depending on the setup). Often manages local subnets/VLAN routing.
  • Primary switch + backup switch: Access layer connectivity. Backup switch provides quick recovery if the primary fails.
  • KVM switch: Operational convenience to control multiple machines from one keyboard/mouse/monitor while keeping systems segmented.
  • SIEM: Central log ingestion + correlation (endpoints, firewall logs, auth logs) for detection and investigation.
  • SOAR: Runs playbooks to automate triage, enrichment, notifications, and safe response actions.
  • Back-UPS: Keeps firewall/switch/SIEM online during short outages to prevent data loss and keep monitoring continuous.

How SIEM and SOAR work together here

  • Collection: endpoints + firewall forward logs to the SIEM.
  • Detection: the SIEM correlates events and generates alerts.
  • Automation: SOAR consumes alerts, enriches context (asset/user), and triggers actions (ticket, Slack/email alert, scripted checks).
  • Controlled response: optional actions like blocking a test IP, disabling a test user, or isolating a lab endpoint (only where supported and configured).
Segmentation SIEM SOAR Back-UPS Operational Resilience

Use case: secure monitoring lab, small office network, repeatable testing and documentation.

Design 2 — Business On-Prem Virtualized Environment (Primary + Backup ISP)

This design represents a more traditional business infrastructure model with redundant internet, virtualized servers, and core services hosted on VMware. It supports centralized identity, business-critical apps, and remote access for employees.

Primary ISP + Backup ISP → Firewall → Switch (+ Backup Switch) → VMware Hosts → Server Workloads ├─ Domain Controller (Primary) ├─ Domain Controller (Backup/Secondary) ├─ Remote Desktop Services (Employees) ├─ QuickBooks Server (DB Manager / App role) ├─ IIS Web Server ├─ SQL Server ├─ Linux Server (apps/services) └─ Exchange Server (or M365 hybrid depending on model)

Core capabilities

  • Redundant ISP: business continuity if the primary circuit fails (failover policy defined at the firewall).
  • Firewall at the edge: VPN/remote access, security filtering, NAT, and centralized logging.
  • Switching layer (+ backup): stable LAN connectivity and reduced downtime risk.
  • Virtualization (VMware): consolidates workloads, improves resource utilization, and simplifies recovery.

Server role explanation (what each VM typically handles)

  • Domain Controller (Primary): authentication, Group Policy, DNS (often), core identity services.
  • Domain Controller (Backup): redundancy for identity services, improves resilience and maintenance windows.
  • Remote Desktop Services: secure access to internal applications without exposing them directly to the internet.
  • QuickBooks Server: hosts QuickBooks Database Server Manager and supports multi-user accounting access.
  • IIS Web Server: internal web apps, intranet services, or app front-ends.
  • SQL Server: database workloads supporting business apps and services.
  • Linux Server: web services, automation tooling, monitoring, or application runtime needs.
  • Exchange Server: on-prem mail (or hybrid / migration path toward Microsoft 365).

Security and operational practices commonly paired with this design

  • Patch management and scheduled maintenance windows.
  • Backups (image-level + app-aware) and periodic restore testing.
  • Least privilege, RBAC, and admin separation.
  • Network segmentation (VLANs) for servers, users, and restricted systems.
  • Central monitoring (availability + logs) and alerting.
VMware Active Directory RDS QuickBooks IIS / SQL Primary + Backup ISP

Use case: SMB/enterprise-style on-prem infrastructure supporting identity, apps, and remote workforce access.

Design 3 — Reference Diagram (Hybrid / Multi-Environment)

Design 3 is a high-level reference diagram showing a more complex environment that blends on-prem connectivity with cloud services and segmented network tiers. It is useful for explaining network boundaries, interconnectivity, and how services flow across multiple environments.

What this design demonstrates (portfolio-safe explanation)

  • Hybrid connectivity: cloud services and on-prem networks connected through secured pathways (VPN / secured access patterns).
  • Segmentation: separation of users, servers, and sensitive workloads to reduce blast radius.
  • Service tiers: identity/services, application tiers, and data tiers represented as distinct components.
  • Resilience: redundancy patterns and structured dependencies for core services.
  • Monitoring readiness: environment structured to support centralized visibility (availability + logs).
