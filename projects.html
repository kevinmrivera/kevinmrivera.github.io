GoDaddy to Cloudflare DNS Migration

Objective: Migrate authoritative DNS from GoDaddy to Cloudflare to centralize DNS management, improve security, and enable Cloudflare protections where appropriate.

Preparation

  • Captured screenshots/exports of all existing DNS records for rollback reference.
  • Documented A, CNAME, MX, TXT (SPF/DKIM/DMARC), and verification records.
  • Identified records requiring DNS-only (mail, SaaS validation, third-party SSL/origin requirements).
  • Reduced TTL values ahead of cutover to minimize propagation delays.

Migration Execution

  • Used Cloudflare DNS scan/copy and manually validated record accuracy.
  • Confirmed all records copied correctly except NS records (replaced by Cloudflare nameservers).
  • Configured proxying selectively for public web services while keeping sensitive services DNS-only.
  • Updated nameservers at registrar and confirmed authoritative DNS cutover.

Issues & Mitigation

  • SSL conflicts when origin hosting managed certificates (e.g., Webflow or other platforms).
  • Incorrect proxy settings causing validation failures (resolved by switching impacted records to DNS-only).
  • Propagation timing differences across regions during cutover.

Post-Migration Validation

  • Validated all websites/subdomains and confirmed mail flow remained stable.
  • Enabled Cloudflare Universal SSL (where appropriate) and confirmed HTTPS behavior.
  • Verified DMARC/SPF/DKIM alignment and rechecked TXT-based verifications.

Technologies: Cloudflare, GoDaddy, DNS, SSL/TLS, DMARC/SPF/DKIM, Proxy vs DNS-only

Microsoft 365 ↔ Google Workspace Calendar Interop (Free/Busy)

Objective: Enable cross-platform Free/Busy availability between Microsoft 365 and Google Workspace tenants to improve scheduling and cross-org collaboration.

Preparation

  • Reviewed Google Workspace Interop requirements and configuration guidance.
  • Verified domain ownership and sharing policies in both tenants.
  • Configured service account / delegated access requirements in Google Workspace.
  • Validated Exchange Online org relationship settings and external availability configuration.

Implementation

  • Configured calendar interoperability settings between Microsoft 365 and Google Workspace.
  • Implemented authentication requirements (OAuth/service account model) and required API permissions.
  • Mapped domains correctly to ensure Free/Busy queries routed to the right tenant.

Issues & Mitigation

  • Free/Busy failures caused by policy restrictions or incorrect sharing scope.
  • Permission scope mismatches for API access.
  • Propagation delays after configuration changes.

Post-Implementation Testing

  • Used test accounts in both environments to validate Free/Busy lookups.
  • Confirmed external visibility restrictions behaved as intended.
  • Validated scheduling experience across desktop and mobile clients.

Technologies: Microsoft 365, Exchange Online, Google Workspace, Calendar Interop, OAuth/API Permissions

Okta to Microsoft Entra ID SSO Migration

Objective: Migrate SSO and identity provisioning from Okta to Microsoft Entra ID to centralize authentication, streamline access management, and align identity with Microsoft 365 infrastructure.

Planning & Preparation

  • Captured and documented the complete Okta tenant configuration (apps, groups, provisioning rules, and license mappings).
  • Reviewed application dependencies and authentication methods prior to cutover.
  • Performed sandbox testing using dedicated test accounts to validate authentication and provisioning behavior.
  • Scheduled implementation during off-hours to minimize production impact.
  • Created step-by-step documentation and internal tutorials for administrators and end users.

Implementation

  • Recreated enterprise applications in Entra ID using prebuilt gallery apps and custom SAML configurations.
  • Configured SAML trust relationships, exchanged IdP metadata, and validated signing certificates.
  • Created security groups and assigned them to applications and license bundles.
  • Configured provisioning, attribute mappings, and group-based access where supported.

Challenges & Mitigation

  • Investigated SAML errors related to metadata mismatch, endpoints, and certificate configuration.
  • Resolved provisioning failures caused by permission scopes and attribute mapping issues.
  • Identified limitations with password transfer functionality and planned user communication accordingly.
  • Remediated access issues (e.g., 404s, permissions) through app configuration and role review.

Post-Migration Validation

  • Verified successful login access across all migrated applications using Entra ID as the IdP.
  • Confirmed all user accounts were correctly federated and pointing to the new IdP.
  • Validated group-based access and license assignments post-migration.
  • Monitored sign-in and provisioning logs to identify and remediate residual issues.

Technologies: Okta, Microsoft Entra ID (Azure AD), SAML 2.0, RBAC, Microsoft 365, Provisioning

Intermedia to Microsoft 365 Email Migration

Objective: Migrate organizational email from Intermedia to Microsoft 365 to consolidate collaboration tools, improve security controls, and centralize administration.

Planning & Preparation

  • Documented the Intermedia tenant configuration: mailboxes, groups, licenses, rules, forwarding, and signatures.
  • Backed up mailboxes using a disaster recovery solution prior to migration.
  • Identified dependencies such as shared mailboxes, distribution groups, and delegated permissions.
  • Scheduled migration during off-hours and planned staged cutover to reduce risk.
  • Selected BitTitan MigrationWiz as the migration tool.

Migration Execution

  • Configured MigrationWiz projects and validated source/destination connectivity.
  • Enabled the “Do Not Duplicate Emails” feature to prevent mailbox inflation.
  • Performed staged migrations to reduce cutover impact.
  • Recreated groups, rules, forwarding, and permissions in Microsoft 365.
  • Updated DNS records (MX, SPF, Autodiscover) to route mail flow to Microsoft 365.

Post-Migration Validation

  • Validated inbound/outbound email functionality and mailbox data integrity.
  • Confirmed folder structure consistency and access to shared resources.
  • Monitored message trace/delivery reports to ensure stable mail flow.
  • Provided user support during the transition and updated documentation.

Technologies: Intermedia, Microsoft 365, Exchange Online, BitTitan MigrationWiz, DNS (MX/SPF/Autodiscover)

VMware to Microsoft Azure Infrastructure Migration

Objective: Migrate on-prem VMware workloads to Microsoft Azure to modernize infrastructure, improve scalability, and enhance disaster recovery capabilities.

Planning & Preparation

  • Audited VMware environment and documented VM inventory and dependencies.
  • Recorded OS versions, resource utilization, storage dependencies, and application requirements.
  • Outlined Azure services required: VMs, database services, Azure Backup, VNet, NSGs, monitoring, and secure admin access.
  • Used Azure Pricing Calculator to estimate costs and right-size workloads.
  • Reviewed licensing needs including Windows Server licensing and CAL requirements.

Migration Strategy & Execution

  • Evaluated migration methods (PowerShell-based recreation vs snapshot/backup restore workflows).
  • Provisioned Azure Virtual Machines aligned with workload specifications.
  • Designed VNet architecture to support segmentation and secure routing.
  • Implemented NSGs to restrict RDP access and enforce least-privilege network controls.
  • Migrated SQL workloads and validated app/database connectivity.
  • Configured Azure Backup policies for workload protection.

Post-Migration Validation

  • Validated RDP connectivity and remote administrative access.
  • Confirmed SQL database accessibility and application functionality.
  • Verified RBAC role assignments were correctly scoped.
  • Tested backups and reviewed recovery procedures.

Technologies: VMware ESXi/vSphere, Microsoft Azure, Azure VMs, VNet, NSG, Azure Backup, RBAC, PowerShell
