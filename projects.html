Okta → Microsoft Entra ID SSO Migration

Identity Entra ID SAML

Objective: Migrate single sign-on (SSO) and identity provisioning from Okta to Microsoft Entra ID to centralize authentication, streamline licensing, and align identity with Microsoft 365.

View approach

Planning & Preparation

  • Captured and documented Okta applications, groups, provisioning rules, and license mappings.
  • Validated application dependencies and authentication methods.
  • Performed sandbox testing with dedicated test accounts.
  • Scheduled implementation during off-hours to reduce impact.
  • Created step-by-step documentation and internal tutorials.

Implementation

  • Recreated applications in Entra ID using gallery apps and custom SAML configurations.
  • Exchanged IdP metadata, validated certificates, and confirmed trust configuration.
  • Created security groups and assigned access and license bundles.
  • Configured provisioning and attribute mappings where supported.
  • Validated authentication flows with test and pilot users.

Post-Migration Validation

  • Verified login access across all migrated applications using Entra ID as IdP.
  • Confirmed users were federated and pointing to the new IdP.
  • Validated group-based access and license assignments.
  • Monitored sign-in/provisioning logs and resolved residual issues.
  • Updated documentation and stabilized support handoff.

Outcome

Centralized identity management, improved authentication visibility, and simplified ongoing access administration with minimal disruption.

Tech: Okta, Entra ID (Azure AD), SAML 2.0, RBAC, Microsoft 365, Provisioning

Intermedia → Microsoft 365 Email Migration

M365 Email DNS

Objective: Migrate email services from Intermedia to Microsoft 365 to consolidate collaboration tooling and improve administrative visibility and security controls.

View approach

Planning & Preparation

  • Documented mailboxes, groups, licenses, forwarding, rules, and signatures.
  • Backed up mailboxes using a disaster recovery solution.
  • Scheduled migration after-hours and selected BitTitan MigrationWiz.

Migration Execution

  • Configured MigrationWiz projects and validated connectivity.
  • Enabled “Do Not Duplicate Emails” to prevent redundancy.
  • Performed staged mailbox migrations to reduce cutover risk.
  • Recreated groups, shared mailbox access, forwarding, and mail flow rules.
  • Transferred DNS records (MX, SPF, Autodiscover) for mail cutover.

Post-Migration Validation

  • Validated inbound/outbound mail flow and mailbox data integrity.
  • Verified group membership, shared mailbox access, and forwarding.
  • Monitored message trace and delivery reports for stability.
  • Provided user support and updated internal documentation.

Outcome

Completed migration with minimal downtime, preserved mailbox integrity, and aligned email with Microsoft 365 identity and security policies.

Tech: Intermedia, Microsoft 365, Exchange Online, BitTitan MigrationWiz, DNS (MX/SPF/Autodiscover)

VMware → Microsoft Azure Infrastructure Migration

VMware Azure NSG/RBAC

Objective: Migrate VMware workloads to Microsoft Azure to modernize infrastructure, improve scalability, and enhance disaster recovery capabilities.

View approach

Planning & Preparation

  • Documented VM inventory, OS versions, dependencies, and resource utilization.
  • Outlined required Azure services (VMs, VNet, NSG, RBAC, Backup, SQL).
  • Used Azure Pricing Calculator to estimate costs and right-size resources.
  • Reviewed licensing requirements (Windows Server licensing, CAL considerations).

Migration Strategy & Execution

  • Evaluated VM rebuild via PowerShell vs. restoration from snapshots/backups.
  • Provisioned Azure VMs and configured VNet segmentation.
  • Implemented NSGs to restrict RDP and enforce least-privilege rules.
  • Migrated SQL workload and validated application/database connectivity.
  • Configured Azure Backup policies for workload protection.

Post-Migration Validation

  • Validated RDP access and confirmed remote administration worked as expected.
  • Confirmed SQL database accessibility and dependent app functionality.
  • Verified RBAC assignments were correct for administrative and operational roles.
  • Tested backup/recovery and monitored performance for right-sizing.

Outcome

Modernized infrastructure into Azure with improved scalability, stronger access controls, and better DR readiness.

Tech: VMware ESXi/vSphere, Azure VMs, VNet, NSG, RBAC, Azure Backup, Azure SQL/SQL on VM, PowerShell
