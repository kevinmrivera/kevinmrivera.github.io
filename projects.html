Okta to Microsoft Entra ID SSO Migration

Objective: Migrate single sign-on (SSO) and identity provisioning from Okta to Microsoft Entra ID to centralize authentication, streamline licensing, and align identity management with Microsoft 365 infrastructure.

Planning & Preparation:

  • Captured and documented the complete Okta tenant configuration including applications, groups, provisioning rules, and license mappings.
  • Reviewed application dependencies and authentication methods prior to migration.
  • Performed sandbox testing using dedicated test accounts to validate authentication and provisioning behavior.
  • Scheduled implementation during off-hours to minimize production impact.
  • Created step-by-step documentation and internal tutorials to support administrators and end users.

Implementation:

  • Recreated enterprise applications in Microsoft Entra ID using prebuilt gallery apps and custom SAML configurations.
  • Configured SAML trust relationships, exchanged IdP metadata, and validated signing certificates.
  • Created security groups and assigned them to applications and license bundles.
  • Configured user provisioning and attribute mappings for supported applications.
  • Validated authentication flows using test and pilot user accounts.

Challenges & Mitigation:

  • Troubleshot SAML errors related to metadata mismatches, endpoints, and certificate configuration.
  • Resolved provisioning failures caused by permission scope and attribute mapping issues.
  • Identified limitations with password transfer functionality and planned user communication accordingly.
  • Investigated and remediated authentication errors (e.g., 404 and access-denied scenarios).

Post-Migration Validation & Stabilization:

  • Verified successful login access across all migrated applications using Entra ID as the primary identity provider.
  • Confirmed all user accounts were correctly federated and pointing to the new IdP.
  • Validated group-based access and license assignments post-migration.
  • Monitored sign-in logs and provisioning logs to identify and remediate residual issues.
  • Provided post-migration support and updated documentation to reflect the new identity architecture.

Outcome:

Successfully transitioned SSO and identity provisioning services from Okta to Microsoft Entra ID with minimal user disruption. The migration resulted in centralized identity management, improved visibility into authentication activity, and simplified ongoing access administration.

Technologies: Okta, Microsoft Entra ID (Azure AD), SAML 2.0, RBAC, Microsoft 365, Identity Provisioning

Intermedia to Microsoft 365 Email Migration

Objective: Migrate email services from Intermedia to Microsoft 365 to consolidate collaboration tools, centralize identity management, and improve administrative visibility and security controls.

Planning & Preparation:

  • Documented the complete Intermedia tenant configuration including mailboxes, groups, licenses, forwarding rules, transport rules, and email signatures.
  • Reviewed distribution groups, shared mailboxes, and access permissions to ensure proper recreation in Microsoft 365.
  • Backed up all mailboxes using a disaster recovery solution prior to migration.
  • Scheduled migration during off-hours to minimize user impact.
  • Selected BitTitan MigrationWiz as the migration tool after evaluating migration options.

Migration Execution:

  • Configured BitTitan migration projects and validated source and destination connectivity.
  • Enabled the “Do Not Duplicate Emails” feature to prevent mailbox inflation and data redundancy.
  • Performed staged mailbox migrations to reduce cutover risk.
  • Recreated distribution groups, forwarding rules, mailbox permissions, and transport rules in Microsoft 365.
  • Reconfigured user email signatures and verified mailbox settings.
  • Transferred and updated DNS records (MX, SPF, Autodiscover) to redirect mail flow to Microsoft 365.

Post-Migration Validation:

  • Validated inbound and outbound email functionality across all users.
  • Confirmed mailbox data integrity and folder structure consistency.
  • Verified group membership, shared mailbox access, and forwarding configurations.
  • Monitored message trace and delivery reports to ensure stable mail flow.
  • Provided user support during transition and updated internal documentation.

Outcome:

Successfully migrated organizational email services to Microsoft 365 with minimal downtime, preserved mailbox data integrity, improved administrative control, and aligned email infrastructure with centralized identity and security policies.

VMware to Microsoft Azure Infrastructure Migration

Objective: Migrate on-premise VMware virtual machines and associated workloads to Microsoft Azure to modernize infrastructure, improve scalability, and enhance disaster recovery capabilities.

Planning & Preparation:

  • Audited VMware ESXi/vSphere environment and documented virtual machine inventory.
  • Recorded operating system versions, resource utilization, storage dependencies, and application requirements.
  • Identified SQL database dependencies and service account requirements.
  • Outlined required Azure services including Virtual Machines, Azure SQL/SQL on VM, Azure Backup, Virtual Network (VNet), Network Security Groups (NSG), and monitoring tools.
  • Used Azure Pricing Calculator to estimate monthly infrastructure costs and optimize resource sizing.
  • Reviewed licensing requirements including Windows Server licensing and Client Access Licenses (CALs).

Migration Strategy & Execution:

  • Evaluated migration methods including PowerShell-based VM recreation and manual snapshot/backup restoration.
  • Provisioned Azure Virtual Machines aligned with production workload specifications.
  • Configured Azure Virtual Network (VNet) architecture to mirror on-prem segmentation.
  • Implemented Network Security Groups (NSG) to restrict RDP access and enforce least-privilege network policies.
  • Deployed and configured RDP access securely through controlled inbound rules.
  • Migrated SQL workloads and validated database connectivity and application integration.
  • Configured Azure Backup policies to protect cloud-hosted workloads.

Post-Migration Validation:

  • Validated RDP connectivity and remote administrative access.
  • Confirmed SQL database accessibility and application functionality.
  • Verified Azure Role-Based Access Control (RBAC) permissions were correctly assigned.
  • Tested backup and recovery processes.
  • Monitored performance metrics and adjusted VM sizing as necessary.

Outcome:

Successfully migrated critical workloads from VMware to Azure, improving scalability, strengthening security posture, enabling centralized RBAC controls, and enhancing disaster recovery readiness within a hybrid cloud environment.

Technologies: VMware ESXi/vSphere, Microsoft Azure, Azure Virtual Machines, Azure SQL, Azure Backup, Virtual Network (VNet), Network Security Groups (NSG), RBAC, PowerShell

Technologies: Intermedia, Microsoft 365, Exchange Online, BitTitan MigrationWiz, DNS (MX/SPF/Autodiscover)
